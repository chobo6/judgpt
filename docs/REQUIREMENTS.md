# 채팅 유해표현 탐지 및 법률 검토 보조 AI — 요구사항 명세서 (v0.1)

## 0. 배경

- 카카오톡 등에서 오간 채팅 원문을 넣으면, 욕설/성희롱/협박/모욕/명예훼손에 해당할 수 있는 표현을 탐지하고, 관련 법 조문·판례를 근거로 "고소 등 법적 대응이 가능한지"를 참고용으로 판단해주는 개인 프로젝트.
- 다른 AI가 제안한 5단계 파이프라인 구조를 초안으로 삼되, 개인 프로젝트로서 범위를 현실적으로 조정한다(§3).

## 1. 전체 파이프라인 (원안)

```
채팅 원문
  ↓
[1. 전처리] 개인정보 마스킹 / 대화 시간·발화자 정리
  ↓
[2. 유해 표현 탐지] 욕설 / 성희롱 / 협박 / 모욕 / 명예훼손 관련 표현
  ↓
[3. LLM 분석] 문맥 / 발화 의도·대상 / 반복성 / 공개성 / 구체적 사실 적시 여부
  ↓
[4. 법률 RAG] 관련 법 조문 / 판례 / 법률 해설
  ↓
[5. 결과] 문제되는 표현 / 적용 가능 법률 / 판단 근거 / 관련 판례 / 추가로 필요한 증거
```

## 2. 출력 예시 (원안)

```
[분석 결과]

⚠️ 발견된 문제 표현: 3건

1. "너 같은 새끼는 사회에서 없어져야 한다"
   유형: 모욕성 표현 / 대상: 상대방 / 위험도: 높음

2. "사진 뿌려버린다"
   유형: 협박성 표현 / 위험도: 높음

3. "한번 만나서 해보자"
   유형: 성적 발언 / 맥락: 상대방의 거부 이후 반복

────────────────────
관련 법률 쟁점: 모욕 관련 법률 / 협박 관련 법률 / 성적 언동 관련 법률
판단 근거: 관련 법 조문 / 유사 판례 / 해당 대화에서 확인되는 사실
추가로 필요한 자료: 전체 대화 내역 / 대화 상대방 정보 / 대화가 이루어진 플랫폼 / 공개 여부 / 발언 전후의 대화
```

## 3. 범위 조정 — MVP와 확장 단계 분리

원안 5단계를 한 번에 구현하기엔 개인 프로젝트로 범위가 크다. 특히 4단계(법률 RAG)는 신뢰할 수 있는 판례·조문 데이터 확보 자체가 별도의 큰 작업이므로, 이것 없이도 가치가 있는 범위(MVP)와 그 이후 확장으로 나눈다.

### 3.1 MVP (1차 목표) — RAG 없이

- 원안의 1~3단계만 구현. 전처리(개인정보 마스킹)와 유해 표현 탐지·문맥 분석을 별도 파이프라인 대신 **하나의 잘 설계된 LLM 프롬프트**로 처리하는 것을 우선 시도한다 — 최신 LLM은 마스킹·분류·문맥판단을 한 번에 꽤 잘 처리하므로, 별도 NER/분류 모델을 먼저 만들 필요는 없다(YAGNI).
- 출력은 §2의 "문제되는 표현 / 유형 / 위험도" 부분까지만. "적용 가능 법률"이나 "관련 판례"는 아직 근거 없이 내지 않는다 — 이 시점에서 법 조문/판례를 언급하면 실제 근거(RAG) 없이 LLM이 지어낼 위험이 크다.
- 성공 기준: 채팅 로그를 붙여넣으면 문제 표현 후보와 위험도가 합리적으로 나오는지 (사람이 보기에 명백한 케이스에서 누락/과탐이 적은지).

### 3.2 확장 (2차) — 법률 RAG 추가

- MVP가 안정화된 후에만 착수한다.
- 조문·판례 데이터 출처를 먼저 정해야 한다(미해결, §6).
- §2의 "관련 법률 쟁점 / 판단 근거 / 관련 판례"를 실제 검색된 근거에 기반해 채운다 — 근거 문서를 못 찾으면 "판단 근거 없음"으로 명시하고 지어내지 않는다.

### 3.3 이번 범위에서 제외

- 실제 소장 작성, 변호사 연결, 신고 접수 대행 등 법적 행위 자체를 대신하는 기능.
- 여러 플랫폼(카카오톡/문자/인스타 DM 등)의 원본 포맷 자동 파싱 — 1차는 사용자가 텍스트로 붙여넣는 것을 전제로 한다.

## 4. 법적/윤리적 고려사항 (필수)

- "고소 가능 여부 판별"처럼 단정적인 표현은 변호사법상 비변호사의 법률사무 취급으로 비칠 위험이 있다. 모든 출력은 **참고용 정보이며 법적 판단이 아니라는 점**을 결과 화면에 항상 명시한다.
- 실제 법적 대응이 필요한 사용자에게는 변호사 상담을 권장하는 문구를 결과 하단에 고정으로 넣는다.
- 채팅 원문에는 민감한 개인정보(실명, 연락처, 신체 관련 표현 등)가 포함될 수 있으므로, 로그 저장 여부와 보존 기간 정책을 §6에서 별도로 정한다.

## 5. 기술 스택 (미정, 초안)

- LLM: 유해 표현 탐지 + 문맥 분석 (모델 미정)
- 법률 RAG(2차): 임베딩 + 벡터 검색, 조문/판례 코퍼스 (출처 미정)
- 프론트/백엔드: 미정 — MVP는 CLI나 간단한 웹 폼 정도로 시작 가능

## 6. 미해결 질문

1. 법률 RAG의 조문·판례 데이터를 어디서 구할 것인가? (국가법령정보센터 Open API, 판례 검색 API 등 — 라이선스/이용약관 확인 필요)
2. 대상 법률을 한국 형법/정보통신망법 범위로 한정할 것인가?
3. 채팅 로그 저장 여부 — 분석 후 즉시 폐기할지, 사용자 동의하에 보관할지.
4. 여러 메신저 포맷(카카오톡 내보내기 등) 자동 파싱을 몇 차 확장에 넣을지.
